Preflight: app map

One request, followed from the button to the screen. Every box names the file and function to open.

The path of one run

1. You press Run preflight. src/components/Preflight.tsx run() POSTs {hackathon, repo, video}.
↓
2. The endpoint validates and fans out. src/app/api/preflight/route.ts POST: parseHackathonUrl allows only *.devpost.com, then three fetches run in parallel.
↓
3. Rules become quotable sentences. src/lib/devpost.ts extractRules uses textBlocks and sentences from src/lib/text.ts, then picks the repository, license, video, new-project and file sentences, and the criteria.
↓
4. Your links are checked. src/lib/github.ts checkRepo (repo and file tree) and src/lib/video.ts checkVideo (oEmbed).
↓
5. Rules meet findings. src/lib/checks.ts buildChecks returns rows with a status, what was found, and the rule quote. criteriaMismatch compares the two criteria lists.
↓
6. The page draws the rows. back in Preflight.tsx, grouped Timing, Repository, Video.

Where the tests are

test/devpost.test.ts: the parser on four real events

Saved copies of the overview and rules pages for Build With AI: Basics, Amazon, Qloo and PayPal live in test/fixtures/. If Devpost changes its template, these fail first.

test/checks.test.ts: every status path

Pass, fail, check yourself and couldn't check, with fake GitHub and oEmbed answers (including a rate limit and a private video).

A practice to reuse

Write down the uncertainty before you build, then settle it with one small test. Here, the spec asked whether YouTube length could be read without a key. One experiment said no, so the plan changed to "check yourself" instead of a guess. See devpost/spec.md, Decisions and Open Issues.
